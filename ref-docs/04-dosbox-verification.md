# 04 - DOSBox Verification of the Original (v2.20)

Run date: 2026-10-02. Scope: settle the UNVERIFIED screen and behavior points in
`01-history-and-behavior.md` and `03-screen-and-ui.md` by running the archived original inside
an emulator and measuring its video and audio output.

Status label used here and propagated to 01/03: **CONFIRMED (DOSBox)** - observed in a
frame-accurate capture of the original program running under emulation. Where a value could
depend on the emulator (CPU speed, cursor blink), that is stated next to it.

---

## Method

### What was run

- Program: `SBAITSO2.EXE` v2.20 with `SBTALKER.EXE` ("SmoothTalker 3.5") and `BLASTER.DRV`,
  from the Internet Archive item `SBAITSO_VGA` (`SBAITSO.zip`), already in the session
  scratchpad from the earlier research pass. SHA-256 prefixes: `SBAITSO2.EXE` f21629b74219f9cf,
  `SBTALKER.EXE` 3f5d86ecdaa4693c, `BLASTER.DRV` c319c68c480fc231.
- The binaries were executed **only inside DOSBox-X**. Nothing ran natively. No binary, capture
  or frame was copied into the repository.
- Emulator: **DOSBox-X 2026.08.31 (SDL2), Flathub `com.dosbox_x.DOSBox-X`**. DOSBox Staging
  0.83.0 is also installed but was not needed; all results below come from DOSBox-X.
- Headless: each run used `xvfb-run` (virtual X display) and `SDL_AUDIODRIVER=dummy`, so
  nothing appeared on the desktop or played through the speakers. The flatpak was granted
  access only to the scratchpad working folder (`--filesystem=<scratchpad>/dosbox-verify`).
  Every run was bounded by DOSBox-X `-time-limit` plus an outer `timeout`, and no DOSBox
  process was left running afterwards.

### Configuration (per run, generated by `run.py`)

```ini
[sdl]
output=surface
[dosbox]
machine=vgaonly          ; 720x400 text mode, 9x16 cells, 70.086 Hz
memsize=16
captures=<scratchpad>/dosbox-verify/cap/<run>
[cpu]
core=normal
cputype=386
cycles=fixed 20000       ; one comparison run used fixed 80000
[sblaster]
sbtype=sb2               ; BLASTER=A220 I7 D1 P330 T3 inside DOS
sbbase=220
irq=7
dma=1
[mixer]
rate=44100
[autoexec]
mount c <scratchpad>/dosbox-verify/c
c:
SBTALKER /dBLASTER
AUTOTYPE -w 4 -p <pace> <scripted keys, with "," as idle time>
DX-CAPTURE /V /A SBAITSO2
```

- `DX-CAPTURE /V /A` records a ZMBV AVI (every emulated frame at 70.086 fps) with the mixer
  audio in the same file, so text and speech share one clock.
- `AUTOTYPE` types the scripted input. Two practical limits were found: its command line is
  cut off at about 512 characters, and each `,` idle token lasts two pace intervals.
- The Q-exit run wrapped the program in a batch file (`RUNQ.BAT`: `SBAITSO2`, then `ECHO`,
  `DIR`) so the screen left behind after quitting is visible.

### Analysis

- `ocr.py`: exact text-mode OCR. Glyph masks were captured from DOSBox-X's own VGA font (a
  `TYPE` of all printable CP437 characters, `fr/ref.png`), and each 9x16 cell is then matched
  bit-for-bit. It also records each cell's foreground/background palette entry and the
  hardware cursor (cell and scanlines). Every changed frame is decoded, giving a timeline of
  text changes with frame-exact timestamps (`<run>.json`). Cells caught mid-update are
  reported as `?`; these occur only on transition frames.
- `segs.py`: speech segmentation of the capture's audio track (5 ms RMS after removing DC
  drift; the DOSBox mixer leaves a slow DC decay after each utterance, which would otherwise
  be mistaken for sound).
- `feat.py` / DTW: spectral features and dynamic-time-warping distance, used to identify
  utterances by comparing them with `SAY <text>` reference recordings.

## Answers

### 1. Letter-by-letter or whole line, and sync with speech

**Answer: whole lines.** Every doctor line appears complete in a single video frame. Nothing is
printed character by character except what the user types, which is echoed per keystroke.
The program prints a line, speaks it, and only after the speech ends prints the next line.

Measured greeting, run G (20000 cycles; name typed slowly so nothing else was queued):

| Event | Printed at | Speech | Gap print -> speech | Gap speech end -> next print |
|---|---|---|---|---|
| `HELLO BOB,  MY NAME IS DOCTOR SBAITSO.` | 20.674 | 20.765-23.375 | 0.09 s | 0.08 s |
| `I AM HERE TO HELP YOU.` | 23.457 | 23.535-24.775 | 0.08 s | 0.07 s |
| `SAY WHATEVER IS IN YOUR MIND FREELY,` | 24.841 | 24.960-27.175 | 0.12 s | 0.11 s |
| `OUR CONVERSATION WILL BE KEPT IN STRICT CONFIDENCE.` | 27.281 | 27.375-30.655 | 0.09 s | 0.09 s |
| `MEMORY CONTENTS WILL BE WIPED OFF AFTER YOU LEAVE,` | 30.748 | 30.850-34.010 | 0.10 s | 0.09 s |
| `SO, TELL ME ABOUT YOUR PROBLEMS.` | 34.101 | 34.245-36.285 | 0.14 s | 0.10 s |
| `>` prompt | 36.384 | - | - | - |

- The blank lines in the greeting add no extra pause.
- Replies behave the same way. Examples: run G reply printed 48.725, speech from 48.93; run C
  reply printed 36.983, speech 37.11-40.90, `User>` prompt at 40.921.
- The print-to-speech gap is the synthesizer's start-up latency and depends on CPU speed. At
  80000 cycles (G2) it fell to about 0.06 s, with the same ordering.
- **A keypress cuts the speech short.** In run K, keys pressed during the greeting stopped
  the current line's speech mid-word. The remaining greeting lines were then printed about
  0.07 s apart without being spoken, and the typed keys appeared at the prompt (`>ab`).
  An Enter typed ahead is consumed as an (empty) input.
- Startup speech, before any text below the banner. The banner is drawn in the first frame
  (0.014 s); the two utterances are identified by DTW against `SAY` references (run H/J):
  - 0.65-1.73 s: "Doctor Sbaitso" (distance 0.69 to `SAY DOCTOR SBAITSO`; about 1.9 to
    the others).
  - 2.19-3.18 s: "by Creative Labs" (0.73 to `SAY BY CREATIVE LABS`). This matches the
    binary string `" DOCTOR SBAITSO       BY CREATIVE LABS "`, whose run of spaces gives the
    0.46 s pause.
  - 3.31 s: `Please enter your name ...` printed.
  - 3.37-4.63 s: "Please enter your name" spoken (0.95 to `SAY PLEASE ENTER YOUR NAME`).
- Name entry: each letter is echoed on screen, then spoken as a letter name (about 0.2 s,
  starting about 0.06 s after the echo; run G, letters at 10.016, 13.569 and 17.122).
- `SAY <text>` prints the text in upper case as the reply line, then speaks it.
- `.PITCH 9` prints nothing. The next reply's median F0 rose from about 90 Hz to about
  133 Hz (run B).
- HELP pages are silent.

### 3. Banner and scrolling

**Answer: the banner is pinned.** Only rows 5-23 scroll; the doctor never writes to row 24.

- Across every run, rows 0-4 (the box) never changed during conversation, including the
  parity flood of about 250 lines.
- When output would pass row 23, the region below the banner scrolls up, sometimes over two
  or three consecutive frames. The prompt then sits on row 23 and row 24 stays blank
  (`fr/H_7700.png`, `fr/E_5800.png`).
- Turn layout, in order:
  - input line `>text` (yellow);
  - the reply on the next row at **column 0** (the greeting lines are the only text indented
    by one space);
  - one blank row;
  - the next `>`.
- Exceptions to that layout:
  - After an age question (`HOW OLD ARE YOU?` / `GIVE ME YOUR AGE?`), the next `>` follows
    with no blank row (`fr/E_6200.png`).
  - After `R`, no reply text is printed. The previous reply is re-spoken and a new `>`
    appears on the very next row (run B, 32.5-34.8 s).
  - Dot commands such as `.PITCH 9` print nothing. One blank row, then `>`.
  - With `.PROMPT ON`, `Computer: <reply>` follows the `User>` line, then a blank row.
- The name prompt and greeting do not move to a new screen. They stay on rows 6-14 and later
  scroll up like everything else.
- These change the whole screen:
  - HELP clears everything, banner included (page 1, `fr/B_2826.png`).
  - `.WIDTH`, `.COLOR` and the N (new patient) key clear the area below the banner and start
    again at row 6.

### 4. Parity-error glitch on screen

Triggered twice: `SAY PARITY` (run C), and an escalating run of profanity (run E). Both
produced the same visual sequence:

1. The screen region below the banner (banner stays) **floods with white lines
   `PARITY ERR ...  <random 1-5 digit number>`**, scrolling far faster than any normal output,
   about 250 lines in about 3.5 s.
2. Part-way through, the lines change to `PARITY ERR ...  <number>  ???`.
3. The flood stops with `PARITY ERR ... RECOVERED`.
4. Then a line `PARITY` (the reply text itself, printed literally), a blank row and the `>`
   prompt (`fr/C_4378.png`, `fr/E_5800.png`).

- No color change, no screen clear and no blinking. Everything stays white on blue.
- Audio: a continuous buzzy tone, roughly 1 kHz falling to about 0.7 kHz, lasts the whole
  flood (about 4 s). A short voiced "parity" follows near the end. The prompt appears while
  the sound is ending.
- `PHEW!   THAT WAS CLOSE!` and `YOU ARE BAD <NAME>. DON'T TRY IT NEXT TIME.` were **not**
  shown in either trigger, although both strings are in the binary.
- Profanity escalation in run E, in order. Each response is printed and spoken; the user
  lines are omitted here:
  1. `YOU MUST NOT TALK IN THIS WAY, HOW OLD ARE YOU?`
  2. Age reply, e.g. `SO YOU THINK YOU ARE BIG ENOUGH, PROOF IT` (sic).
  3. `DON'T GET FRESH`
  4. `SHAME ON YOU`
  5. `I REFUSE TO COMPUTE THIS FILTH`
  6. `I WILL GET PARITY ERROR IF YOU KEEP TALKING IN THIS FZA!$[{? WAY.` The garbage
     characters are printed literally.
  7. The next profanity triggers the parity flood.
  8. Afterwards the group continues: `GIVE ME YOUR AGE?`, `NO NONSENSE, DEAR`.

  This follows the order of the response group in the binary.

### 5. Exit menu

- **BYE** (keyword):
  - The reply, e.g. `GOOD BYE, SO LONG!`, is printed and spoken.
  - **On the very next row, with no blank row**, `<C>ontinue  <N>ew patient  <Q>uit  .....`
    appears in white at column 0 (`fr/D_1800.png`).
  - No cursor is shown and no `>`. The menu itself is not spoken.
- **`.QUIT`**:
  - Prints `GOOD BYE BOB` (just `GOOD BYE <NAME>`, no "AND HAVE A NICE DAY") and speaks it.
  - Then shows the same menu on the next row (`fr/D_3700.png`). It does **not** return to DOS
    directly.
- **Bare `QUIT`** (no dot) shows the menu immediately, with no goodbye line (run L).
- **Bare `EXIT`** is not a command. It got `THAT'S TOO BRIEF` (the short-input group).
- Keys at the menu:
  - **C**: not echoed. One blank row, then a new `>`. The conversation continues and the
    history stays on screen (`fr/D_2300.png`). No speech.
  - **N**: rows 5-24 are cleared, the banner stays, and `Please enter your name ...` is
    printed on row 6 and spoken. The "Doctor Sbaitso, by Creative Labs" intro is **not**
    repeated. A full new greeting follows with the new name.
  - **Q**: the program exits to DOS without speaking. Rows 5-24 are cleared to the DOS
    default (light gray on black) and DOS output continues there. **The blue banner stays
    on screen** at the top (`fr/D2_2300.png`).

### 6. Empty Enter, repeats, HELP, dot commands

- **Empty Enter.** The empty line stays as a bare yellow `>`; the reply is on the next row.
  Replies are drawn from the empty-input group in an order that differed between runs, and
  the literal word **`ENTER`** is one of the replies. It is printed and spoken ("enter"); it
  is the group's label string leaking into the output.
  - Run A, three presses: `DON'T JUST PRESS ENTER, TALK TO ME`, `ENTER`,
    `DON'T JUST PRESS ENTER, TALK TO ME`.
  - Run H, seven presses: `PLEASE TYPE SOMETHING`, `ENTER`, `DON'T BE SHY, TALK TO ME`,
    `DON'T BE SHY, TALK TO ME`, `ENTER`, `PLEASE TYPE SOMETHING`,
    `HAY, TYPE SOMETHING SENSIBLE, WILL YOU?`.
  - No escalation to `ARE YOU SURE...` / `DO YOU WANT ME TO SHUT UP AND QUIT?` occurred
    within seven presses.
- **Repeated input.** The same line typed again in a row:
  - Run A: 1st `IS THERE SOMEONE ELSE THAT YOU HATE?`, 2nd `SAY SOMETHING ELSE`,
    3rd `PLEASE DON'T REPEAT`, 4th `HOW OLD IS YOUR MOTHER?` (a keyword reply returns).
  - Run J: 2nd `I DON'T LIKE PEOPLE REPEATING`, 3rd `PLEASE SAY SOMETHING ELSE`,
    4th `THIS IS GETTING BORING, JUST NOW WERE YOU TALKING ABOUT SOMETHING ELSE?`.
  - Replies are randomized: "i feel sad" got three different answers in three runs.
- **HELP.** Three silent pages:
  - Page 1 (`fr/B_2826.png`) clears the whole screen, banner included. It shows a centered
    white title `Sound Blaster Acting Intelligent Text to Speech Operator` with a
    double-line underline, then the description (indented one space) and the yellow
    `Enter <R> ...` line. The dot-command table follows at column 0, and the last line is
    `Hit <M> now for More HELPs. However, you get more fun exploring them yourself.`
  - **M** shows page 2 (`fr/B_3400.png`), with the banner redrawn: the hints (topics, CALC,
    SAY, bad language) indented one space, then `Hit <M> now for More Hints, but you will
    miss the fun.`
  - **M** again shows page 3 (`fr/B_3639.png`), banner kept: three intro lines, then 14
    keywords in a 5-column grid (WHAT IS, THINK, FEEL, BITCH, HATE, ENVY, KID, NICE DAY,
    THANK, PC, BOSS, RICH, HELP, SUFFER), a blank row and a `>` prompt.
  - The previous conversation is not restored.
- **`.PITCH 9`** produces no screen output at all: the input line, a blank row, a new `>`.
  The effect is audible only (see 1).
- **`.PROMPT ON`** changes the prompt to yellow `User> ` and prefixes replies with
  `Computer: `. The command's own line is still shown with the plain `>`. **`.PROMPT OFF`**
  printed an empty `Computer:` line, then `>` on the next row with no blank row
  (`fr/C_3500.png`).
- **`.WIDTH 40`** clears the screen and draws the compact two-line banner (`Sound Blaster`,
  yellow `DR S B A I T S O`, green `(c)Copyright Creative Labs,Inc.1992`) in double-width
  characters. Conversation continues with the same colors. HELP there prints
  `NO HELP FOR 40 COLUMNS. TRY:   .WIDTH 80` (`fr/I_2600.png`). **`.WIDTH 80`** clears and
  redraws the normal banner, with `>` on row 6.
- **`.COLOR 4`** clears the screen and redraws the banner and prompt on a red background for
  the whole screen, banner included (`fr/I_5100.png`). `.COLOR` with no number prints
  `Enter color number (0-7)` and takes a digit (2 gave green, `fr/I_7100.png`). Text colors
  stay the same.
- **CALC.** `CALC 2+3` printed ` =  5` and `CALC 10/4` printed ` =  2.5`; the expression is
  not echoed. `WHAT IS 12*4` printed `12*4 =  48`. All are white with **no** `Computer:`
  label while the prompt is off.
- **`R`** re-speaks the last reply without printing it (run B, J). In run A the emulator
  stopped with `E_Exit: Corrupt MCB chain` on an `R` typed after four repeats. This was not
  reproducible (runs B and J ran `R` normally), so it is treated as an emulation
  incident, not program behavior.

### 7. Timing

| Quantity | Measured | Note |
|---|---|---|
| Banner draw | first frame after start (0.014 s) | instant |
| Doctor text reveal | whole line in one frame | no typewriter |
| Line printed -> its speech starts | 0.08-0.14 s (20000 cycles); about 0.06 s (80000 cycles) | synthesizer latency, CPU-dependent |
| Speech end -> next line printed | 0.07-0.11 s | |
| Speech end -> `>` prompt | -0.04 to +0.12 s | prompt appears as the speech ends |
| Greeting, Enter to prompt | about 15.7 s for the six lines (run G) | |
| Name letter speech | about 0.2 s per letter, about 0.06 s after the echo | |
| Startup | "Doctor Sbaitso" 0.65 s, "by Creative Labs" 2.19 s, prompt text 3.31 s, prompt speech 3.37-4.63 s | |
| Cursor | 1-scanline underline on scanline 14 (0-based) of the 16-line cell, white, at the cell after `>` | |
| Cursor blink | 8 frames on / 8 frames off at 70.086 Hz = **114 ms on, 114 ms off** (228 ms period) | DOSBox-X's VGA emulation |
| Cursor visibility | shown only while waiting at `>`. Hidden during name entry, while the doctor is speaking, and at the C/N/Q menu | |
| Parity flood | about 3.5 s of scrolling, about 4 s of tone | |

The cursor blink rate is the emulated VGA hardware rate, not something the program sets. It
contradicts the 229 ms-per-phase figure in 03, which came second-hand from FreeVGA. DOSBox-X
toggles the cursor every 8 frames (a 16-frame cycle), which matches the usual reading of
"blinks every 16 frames" as a full on+off cycle.

## Corrections to 01/03

1. **03, user text color:** the typed conversation input is **yellow** along with the `>`, not
   white. Gap item 8's advice ("keep yellow only for the `>`") is wrong; the current app's
   yellow user text is actually faithful. The name typed at the name prompt is white.
2. **03, reply indentation:** only the greeting lines are indented by one space. Conversation
   replies start at column 0.
3. **03, name input position:** typing starts at column 26, directly after the ellipsis (the
   prompt string is 26 characters), not "around column 27".
4. **03, cursor blink:** measured 114 ms on / 114 ms off in DOSBox-X, not 229 ms per phase.
   The suggested CSS `animation: blink 458ms` should be about 228 ms. The cursor is hidden
   during name entry and while the doctor speaks.
5. **03, scrolling:** rows 5-23 scroll and the banner is pinned. Row 24 is never written. HELP
   page 1 is the only screen that removes the banner (it returns on page 2).
6. **03 / 01, exit menu:** it follows the goodbye line on the next row with no blank row and
   no prompt or cursor. Q leaves the banner on the DOS screen. N clears and re-prompts for
   the name without the "Doctor Sbaitso, by Creative Labs" intro.
7. **01, `.QUIT`:** it does not quit directly. It prints `GOOD BYE <NAME>` (no "AND HAVE A
   NICE DAY"), speaks it and shows the C/N/Q menu.
8. **01, bare QUIT:** it shows the C/N/Q menu directly (the bertrandom port's behavior matches
   the original). Bare EXIT gets a short-input reply.
9. **01, parity sequence:**
   - The "hang" is actually a fast flood of `PARITY ERR ...  <number>` lines, then lines
     ending in `  ???`, then `PARITY ERR ... RECOVERED` and a literal `PARITY` line.
   - `PHEW!   THAT WAS CLOSE!` and `YOU ARE BAD <NAME>...` did not appear.
   - It is accompanied by about 4 s of falling tone, not speech.
10. **01, `User>` / `Computer:`:** these appear only after `.PROMPT ON`. The default prompt is
    a bare `>` and CALC output is unlabeled by default. The summary line in 01 ("User input
    is shown on a `User>` prompt line, and CALC output is labeled `Computer:`") describes the
    `.PROMPT ON` mode only.
11. **01, empty Enter:** replies come in no fixed order, and the literal word `ENTER` is one of
    them. The "escalating" order is not what the program does in practice, at least within
    seven presses.
12. **01 / 03, startup:** before the name prompt the program says "Doctor Sbaitso" and then
    "by Creative Labs", both with only the banner on screen. It then prints the name prompt
    and speaks it. No splash screen.
13. **01, CALC format:** `CALC 2+3` shows ` =  5` (expression not echoed, two spaces after
    `=`), while `WHAT IS 12*4` shows `12*4 =  48`.
14. **03 gap 10 (text reveal):** confirmed. Print the line, speak it, print the next line when
    the speech ends. A keypress during speech cuts the speech, and the remaining queued lines
    are printed unspoken.
